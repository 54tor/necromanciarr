# Changelog

Format inspiré de [Keep a Changelog](https://keepachangelog.com/fr/1.1.0/).

## [Unreleased]

### Added
- `sources list`, `sources test <name>`, `proposals list --source`, and the Sources view.
- Indexer search answers are cached (6 h, 24 h when empty; no download link, key or magnet is ever stored), a search that ran to the end is not repeated for 7 days, and a `.torrent` whose infohash is already a candidate is never downloaded again; the Match result gains `cache_hits` per indexer.
- Indexer request budgets (per run and per day over a sliding 24 h window, kept across restarts, one indexer at a time, minimum interval and `Retry-After` honoured); reaching one gives the reason `indexer_budget_exhausted`, which is not a failure.
- First release: finds on a library provider the torrents whose files the library already holds (through Radarr and Sonarr), proves every file by the piece SHA-1, rebuilds the torrent with links in a separate link folder and seeds it in qBittorrent; nothing happens without an accepted proposal and the library is never written.
- Proposals for full torrents, partial annexes, partial packs, conflicts and native cross-seed, with groups and a chosen primary; Force for a paused partial annex.
- Torrent-side deduplication (`dedupe plan/apply`) and broken-link repair (`repair scan/apply`), guarded by a client recheck.
- Cross-seed integration: sandboxed import of its `config.js`, `auto/delegate/native/off` modes, webhook notification.
- rclone hash providers (`fsProviders`) with a per-mount capability cache.
- SFTP file system providers (`fsProviders` type `sftp`) with pinned host keys (the SFTP volume itself lands later in this release: until then an `sftp://` root is refused at startup).
- pathMappings accepts an `sftp://<provider>/<path>` from side, compared case-sensitively; a remote link folder needs such a rule (client_path_unmapped otherwise), never gets skip_checking (identity_unproven), and a remote volume that does not answer leaves Link and Seed proposals for the next run (remote_unavailable).
- dedupe and repair read and write through the volume registry: on a volume without atomic replace a dedupe proposal is not applicable (no_atomic_replace) and repair refuses, with no fallback; on an `sftp://` volume dedupe proves by a full read announced as warning.dedupe.full_remote_read, and a remote path needs an sftp pathMappings rule before a client recheck (client_path_unmapped).
- CLI with `--json`, web interface and API (bearer token, jobs), `doctor` diagnostics, Docker image (amd64, arm64, riscv64).
- `seedTags` (`NECROMANCIARR_SEED_TAGS`): tags set on every added torrent; the list replaces the default `necromanciarr` tag. `doctor` shows the category and tags.
- `NECROMANCIARR_SEED_CATEGORY` sets the seed category (`linkCategory`) from the environment.
- `partialMaxMissingPercent` (`NECROMANCIARR_PARTIAL_MAX_MISSING_PERCENT`, default 100): partial torrents missing more pieces are not proposed; `status` lists them with the reason `missing_pieces_above_cap`, and each Verify applies the current cap.
- `language` (`--language`, `NECROMANCIARR_LANGUAGE`, default `fr`): display language of the CLI, web interface, diagnostics and logs (`fr` or `en`).
- CLI text and help, API error messages and action descriptions follow `language`; `GET /api/status` reports it; error codes never change.
- The web interface switches to `language` once the server answers (browser language until then, French by default); navigation, access-token dialog and code labels are translated, with no script evaluation so the strict content security policy is unchanged.
- The web interface has a left sidebar (icons only between 768 and 1023 px, a drawer on narrow screens) with count badges for pending proposals and failed diagnostic checks, a skip link, and a page header with a toolbar area.
- The web interface gains an accessible data table (sortable columns, keyboard row navigation, stacked cards on narrow screens, paging), status pills that always show an icon and a label, and a confirmation dialog that can list the affected items and require a typed phrase; the sidebar scrolls on short screens.
- The Getting started and Stages pages are tables: diagnostic checks are grouped by family (configuration, services, storage, sources, volumes) with a status pill, the server-rendered detail and hint, the duration and a per-check rerun button; stage jobs are listed newest first with a summary of counters and translated reasons, and a result dialog.
- The Proposals page is a dense table (kind, decision, source when available, % verified, missing pieces, group with its primary, step, warnings) with filters, a search by name and an expandable detail (missing media, ambiguous and excluded files, warnings). Accepting never works on a free selection: checkboxes exist only on pending proposals and only to reject them, after a confirmation that lists every name (one request per proposal); `accept-group` handles one group at a time and lists its members; Force exists only for a partial annex seeded paused, after typing a confirmation word; outdated proposals are disabled.
- `GET /api/proposals` returns `updated_at` (latest of creation, decision and last application step) and the Proposals page shows it in an Updated column.
- The Deduplication page is a dense table (torrent-side file, library target, kind, proof, bytes to read, decision, applicability with its reason, warnings) with a dry-run box checked by default. A real replacement, one row or all accepted proposals, is sent only after typing a confirmation word in a dialog that lists the files; a dry run never modifies anything, and bytes to read are shown before any acceptance. Non-applicable rows (ambiguous, isolated copy) stay listed with a disabled button and their reason; plan warnings follow the interface language.
- The Links page has two tabs: recorded links (paged by the server, state filter, not-compared marker, partial-inspection notice) and repairs (dry run by default, a typed word before a real repair; ambiguous, lost and recheck-pending repairs are listed but not applicable).
- English version of the reference documentation (`docs/reference/en/`).
- Torznab indexers (`torznab`, Prowlarr feeds) and `sourceOrder`: URLs and keys are masked everywhere; `doctor` checks each indexer (`torznab:<name>`, capabilities only, no quota spent) and Prowlarr (`prowlarr`, indexers missing or disabled).
- `NECROMANCIARR_SECRET_KEY` (`api-key --secret`) seals indexer torrents at rest (AES-256-GCM); a configured `torznab` indexer now requires it, and `doctor` checks it (`secret-key`) by unsealing the stored blobs. Candidates record their `source` (`provider` for existing ones).
- `trackers`: announce URLs per tracker (passkey from the environment), injected at seed time; announce URLs are always shown as `scheme://host/***`, and `config check` lists only hosts, aliases and variable names. An announce URL holding a space (U+00A0 included, so a variable value ending with a space), a control character or more than 2048 bytes, or an entry with more than 512 URLs, is refused at load.
- Announces are injected before qBittorrent (config `trackers` first, else the announce of a same-infohash indexer torrent); proposals without any announce show `no_announce` and are neither linked nor seeded. The injected `.torrent` exists only in memory during the add; `proposals list` shows `seedable` and `announce_source` (`config`, `indexer`, `none`), `status` counts `no_announce`, and the Proposals page shows a "No announce" pill explaining that linking will be refused (Accept stays enabled). `trackers` is required to seed provider torrents; restart the service after editing it. Adding a `trackers` entry lifts `no_announce` without re-verifying and clears the sealed indexer torrent it replaces.
- Match searches the Torznab indexers, in `sourceOrder`, for the library files the provider does not cover: identifier search when the indexer's capabilities allow it, else text search (`<title> <year>`, `<title> S01E02` or `S01`, never `S00E00` from unknown values), only in the categories its capabilities advertise; results are filtered by size before any download, downloaded one at a time at `minInterval` (at most 3 per group and run), and kept only if one file has exactly the size of a local file still without a candidate (else `torznab_no_exact_size`). A kept torrent becomes a `fetched` candidate with `source` `torznab:<name>`, the indexer's `tracker` (else `torznab:<name>`) and its sealed copy; a candidate already known for the same infohash and tracker keeps its source, except a `stale` one, taken back at `fetched`. The stage result reports `indexers` (`torznab_queries`, `torznab_downloads`, `budget_exhausted`, `magnet_only` per source).
- Verify falls back to indexers of the same tracker when the library provider has no `.torrent`: only a torrent whose computed infohash matches is kept, stored without announce and sealed with `NECROMANCIARR_SECRET_KEY` (not sealed, and no key needed, when a `trackers` entry covers the tracker); the candidate's `source` becomes the indexer; the stage result lists `searched_sources`, and new reasons `indexer_unavailable`, `indexer_access_denied`, `indexer_hostile_response`, `foreign_download_host` and `magnet_only` explain skipped indexers and items (an unavailable, refusing, hostile or unreadable indexer is set aside for the rest of the run, and like an exhausted budget leaves the candidate for the next run).

### Changed
- Web interface redesigned: sidebar navigation, page toolbars, dense sortable tables, status pills; cards only on narrow screens; fully translated (fr/en).
- Server log lines are translated and carry a stable `code` attribute (`job_failed`, `server_listening`, ...); the `serve` startup line is now a structured log line (`code=server_listening`) and follows `language`, as do the other `serve` messages; Go HTTP server errors and handler panics are logged through the same coded, redacted log.
- `links list` returns a stable `reason` code with a translated `label` instead of an English sentence; dedupe reasons are stable codes too, and `warnings` of `status`, stage results and `dedupe apply`/`repair apply` are `{code, text}` objects; mount advice and cross-seed mode warnings are translated.
- The page shown when the binary is built without the web interface follows `language` (title, `make ui` hint, `<html lang>`).
- `doctor` results carry a stable `code` and are rendered in the configured language.
- Proposal warnings are stored as translatable messages and returned as `{code, text}`; reasons come with translated labels (`reason_labels`, `label`). Warnings stored by earlier versions are still shown as they were saved.
- Proposal warnings are now stored as structured messages; a database written by this version cannot be read by an older binary.
- A link kind failure (`cross_device`, `no_link_dir_on_same_device`, `link_kind_refused`) now tells the cause and the setting to change.

### Security
- Every output also masks, inside any URL, credentials, parameters named like a passkey (`passkey`, `pk`, `authkey`, `torrent_pass`, `key`, `uid`, `apikey`, `secret`, `token`) whatever their length, and any path segment or parameter holding a hex or base64url word of 16 characters or more, including percent-encoded, double-encoded and upper-case spellings; an infohash shown inside a URL is masked too. JSON-escaped URLs (`https:\/\/…`) are masked whole, token-like host labels are masked, a `trackers` value shorter than 8 characters is masked only inside URLs (exactly, whatever the parameter name) and named by `config check` and `doctor` (`tracker_value_too_short`); redacted JSON stays valid with short secrets, and CLI text drops control characters before masking.
- A sealed indexer torrent is erased in the same database statement that fails or invalidates its candidate or closes its last open proposal (`applied`, `rejected`, `superseded`), and after 30 days without update; Verify keeps only an announce-free copy of every `.torrent` (a `.torrent` it cannot sanitize fails that candidate only), and the `torrent` column refuses `announce`, `announce-list`, `url-list`, `httpseeds` and `comment`.
- Force copies each linked media sharing a missing piece out of the library before starting, or refuses.
- Rechecks resume only torrents that were running; an incomplete torrent added by Seed must show paused.
- Text output strips terminal control characters; `config.js` cannot read this tool's variables; response bodies are capped; redirects are refused.
